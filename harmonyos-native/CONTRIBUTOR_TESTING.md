# deve 分支验证交接（2026-11-05）

本轮按用户要求只提交 deve，由其他贡献者完成鸿蒙测试后决定合并。README.en.md 用户已有改动不提交。

## 本轮实现

1. 手动同步从仅推送扩展为先推送、后分页拉取；按账号保存游标。
2. 服务端递增变更序号、固定分页水位、旧记录稳定客户端 id、普通编辑与删除接口纳入同步。
3. 修复界面 ScopeSetup 直接上传时缺少版本封装的问题。
4. 修复冲突只换标题不换波形、上传中编辑被清空操作编号、本机确认落盘失败仍报成功。
5. 冲突保留发送快照和后续编辑；首次上传期间删除会留下可同步的墓碑。

## 贡献者优先验证

- 拉取 deve 后执行 npm test，然后 npm run harmonyos:native:build，处理可能的 ArkTS 编译限制。
- 使用独立验收数据库与测试账号，避免直接迁移真实库；迁移说明见 server/SYNC_PROTOCOL.md。
- 检查实际界面保存的原生参数可上传，换客户端后可拉取并恢复两通道波形。
- 在另一客户端改名/修改参数/删除，手动同步后原客户端应接收变更。
- 两边同时修改时应保留原记录和冲突副本，不能用服务器标题搭配旧本机波形。
- 上传时继续编辑或删除；下一次点击同步应发送剩余操作，不可丢失或复活删除记录。
- 模拟请求响应丢失、本机写盘失败、游标保存失败；重试不得重复创建。
- v1 网页记录应明确跳过；游客和其他账号记录不应混入。
- 验收按钮、输入框、同步提示与滚动布局，记录设备/系统/提交号及实际现象。
